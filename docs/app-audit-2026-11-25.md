## Verdict

The engine is strong: strict TypeScript, 1,169 client + server tests green, chats in SQLite, a throttled persisted
store with 18 migrations, rate limits and body limits on every server route, account deletion, crisis and report
flows, the model behind every character line. What limps is everything **around** the engine that a real launch
needs: money, crash visibility, keeping a user's friends when they change phone, and a codebase that is growing
faster than it is being split.

## P1: architecture (senior-level debt that slows every change)

6. **The store is a 7,717-line god object** (`src/store/use-app-store.ts`, plus 1,376 lines of types) and has no
   test file of its own; the logic is tested where it was pulled into `src/lib`. It is also the hottest collision
   file between the three agents. Split into zustand slices with the same persisted shape (no migration): chat &
   messages, wallet & plans, friends & relationships, moments & plans, settings. One slice per commit, each with
   tests, behaviour unchanged.
7. **Screens over 1,000 lines**: `create-character.tsx` 1,179, `(tabs)/chat.tsx` 1,152, `message-bubble.tsx` 1,120,
   `chat/[id].tsx` 1,056. Pull hooks and sub-components out (the bubble renders in every chat: smaller and memoised
   is also faster on the A51).
8. **Rate limits live in memory** (`server/src/rate-limit.ts`): fine on one Fly machine, but they reset on every
   deploy and stop working the day there are two machines. Move the per-user day budgets to Postgres (one row per
   user per day) before scaling.
9. **Expo SDK 58 is out; 28 packages behind** (`npx expo-doctor`). The upgrade needs a new APK anyway, so it joins
   the native batch rather than a separate build.
10. **No end-to-end tests.** 1,169 unit tests, zero tests that tap through the app. Add Maestro flows for the five
    chains that must never break: onboarding to first chat, send and receive, a call, a purchase (sandbox), delete
    account. Runs on the A51 before every release.

## P2: product and structure (owner's call where users would notice)

11. **Feature sprawl.** 37 top-level routes: radio, quiz, photo booth, streams, dates, board, diary, secret notes,
    alarms, bedtime, world, lore, frames, scenes and more. The product's first job is talking to a character like a
    real person. Each extra feature is QA surface, 14 locales of text and model cost. Proposal for launch: the
    first build shows chat, calls, moments, memory, plans/alarms; the rest stays in code behind a flag and comes
    back one by one as updates (also gives the store "what's new" news). **Needs the owner's yes.**
12. **Pushes are written ahead on the phone only.** If the user does not open the app for days, no new texts get
    written, which is when a companion app needs them most. Server push (FCM / APNs) needs Firebase, an Apple
    account and a new APK: plan it into the native batch once the Apple account exists.
13. **App weight**: 40 MB of assets, 11 MB of it the 84 stills. Fine for now; later, stills and story portraits
    can load from storage instead of the bundle.
14. **Model on a free key.** Quality evals and the final model choice wait for the paid key
    (`docs/road-to-launch.md`).

## One native batch (one new APK, one test pass on the A51)

SDK 58 upgrade, Sentry, RevenueCat, Sign in with Apple / Google, later FCM. Guard each with
